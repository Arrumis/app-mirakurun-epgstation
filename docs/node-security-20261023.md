# Node.jsのセキュリティ更新と移行確認

2026年10月21日のNode.jsセキュリティリリースに対応し、2026年10月23日に実環境へ反映しました。

## 更新内容

- Mirakurun: 4.1.2から4.1.5、Node.jsは24.16.0から24.22.1。
- EPGStation: 2.10.0から公式の3.0.0-beta2、Node.jsは18.20.3から24.22.1。
- EPGStationのベースイメージとNode.jsの取得元をdigestで固定。
- エンコードスクリプトをES moduleへ変更し、FFmpegの進捗にある`KiB`にも対応。
- FFmpeg 7.0を維持し、Debian 13向けのビルド依存と実行時SDLライブラリを調整。

## 確認結果

- DBと設定をバックアップし、旧コンテナのイメージを退避。
- 別DBへ復元し、録画ファイルを読み取り専用で参照する候補コンテナで移行を確認。候補から実チューナーへのストリーム取得は遮断。
- 本番切り替え前後で録画済み1,514件、予約58件、ルール19件の件数と一覧IDが一致。
- DB移行でマイグレーション履歴が3件から5件となり、空の`encode_queue`が追加された。番組表の件数変化は通常の更新によるもの。
- Mirakurunのサービス114件を取得し、起動後の例外・バッファあふれ等のエラーカウンターは0。
- EPGStationの画面はHTTP 200で表示され、ChromiumでJavaScript例外なし。
- 時刻指定の30秒予約で開始・終了、サムネイル作成、H.264エンコードを確認。
- TSとMP4はともに約32.4秒で映像・音声を含み、再生用RangeリクエストがHTTP 206で65,536バイトを返した。
- 検証用録画だけをAPIで削除し、既存の録画・予約・ルールの一覧が維持されていることを再確認。

旧版の18時開始予約が動いていなかった件は、ソースコードと予約情報を確認した結果、録画済み番組の重複除外による正常動作だった。予約タイマーの不具合としては扱っていない。

v3はベータ版です。今後の予約録画も継続して確認してください。v2へ戻す場合はREADMEの手順に従い、更新前のDBと設定を復元してください。
